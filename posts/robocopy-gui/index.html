Robocopy is the best file-copying tool built into Windows, and one of the hardest to remember: dozens of switches, several of which can delete files at the destination. Mirror lets you build the command visually instead. It covers every option in robocopy /? (97 settings), explains what each one does, and warns before anything can delete files. It runs entirely in your browser; nothing is uploaded.

Mirror began as a single-page Robocopy GUI in 2025 and was redesigned as part of Conduit, a pair of command builders that share one design system. Its sister app is Fetch, the Wget builder. This post covers why I wanted it, what it does, and how the two apps are built from one source.

2 The problem with Robocopy

Robocopy can do almost anything with files: copy only what changed, keep permissions and timestamps, retry over a flaky network, copy with many threads at once, log everything, and run on a schedule. All of that is switches on one command line, and the switches are terse. /MIR, /PURGE, /MOV and /MOVE look harmless and can each remove files, either from the destination or from the source. A typical backup line ends up looking like this:

robocopy "D:\Projects" "\\server\share\backup" /E /XO /MT:16 /R:3 /W:5 /Z /FFT /NP /LOG:backup.log

If you write one of these a year, you look every switch up again each time, and you hope you did not mix up /MOV and /MOVE. I wanted a form that writes the command for me, says in plain words what each part does, and makes the dangerous parts impossible to miss.

3 A quick tour

  1. Pick a starting point. Choose a preset (Daily backup, Exact mirror, Archive with permissions, Fast LAN copy, or Move and clean up) or start from scratch.
  2. Fill in the tabs. Locations, What to do, Filters, Preserve, Performance, Automation, Logging and Advanced. Rarely used options stay hidden until you turn on Show advanced.
  3. Watch the command. It updates as you choose, with every flag explained.
  4. Add to queue. Build several jobs, reorder them, then download one .bat or .ps1 script. Stop on first failure is on by default.
CautionSome options delete files

The /MIR (mirror), move and purge options can remove files from the destination. The app shows a clear notice for each of them before anything can be deleted, so read it before you run the script.

Every command gets one of three labels: “No destructive options”, “Review before you run”, or “This can delete files”. Unless the label is the first one, and while Preview only (/L) is off, the warning comes with a Turn on preview only button, so the first run just lists what would happen. Mirror also points out combinations that do not do what you might expect: copy threads cannot be combined with a packet pause, telling Mirror to leave extra files alone means it will not delete them, and adding /PURGE to /MIR changes nothing because mirror already purges.

Other ways in

  • Find an option. Type a name or a flag, such as retry or /MT, to search every tab at once.
  • Paste a command. Paste an existing robocopy command and the form fills in. Flags the builder does not recognise are kept under Advanced.
  • Command palette. Ctrl+K jumps to any option, preset or page, and Ctrl+Enter adds the current command to the queue.
  • Profiles. Save a full set of options and load it later. Profiles, the queue and the form are remembered in your browser.

4 How it works

One list of options drives everything

Each Robocopy option is written once, as a small declarative entry: its flag, a label, a one-line explanation, which tab it belongs to, whether it is advanced, and, for the risky ones, a risk level and the warning to show. For example, the “What to do” choice lists Copy, Mirror (/MIR, “Deletes in destination”), Move and Move files only. The form, the colored command, the per-flag explanations, the search, the command palette and the risk label are all generated from that one list, so adding an option in one place makes it show up everywhere.

Reading a command back in

Pasting a command runs the same list in reverse. The parser splits the text into tokens while keeping quoted paths together, joins lines that were continued with ^, and drops a leading robocopy or robocopy.exe. Robocopy’s switches are case-insensitive, so it matches them in upper case, and it understands both bare switches (/E) and switches with values (/MT:16, /LOG:backup.log). Switches that take a list, such as /XD for skipped folders, consume the following words until the next switch. Whatever is left is positional: the first two are the source and destination, and anything after them becomes the file patterns. Anything it does not recognise is not thrown away but kept in the Extra flags field under Advanced, so a pasted command never silently loses part of itself.

Scripts that stop at the right time

Robocopy does not use exit codes the way most programs do. Codes 0 to 7 all mean success (they report whether files were copied, skipped or found extra at the destination), and only 8 and above mean that something failed. A script that treats any non-zero code as an error would stop after every successful copy. So when stop on first failure is on, the .bat export checks if errorlevel 8 goto :failed after each Robocopy job, and the PowerShell export checks $LASTEXITCODE -ge 8. Both exports are written with Windows line endings, and the .ps1 file is saved as UTF-8 with a byte order mark.

Two apps, one source

Mirror and Fetch share one source file, design/shell.html, which contains both tools plus a page documenting the design system. A small Node script, design/build.js, turns it into two self-contained index.html files: it keeps one tool’s definitions, swaps in that app’s name, accent color, defaults and navigation, replaces sample paths with ones under %USERPROFILE%, and adds saving to browser storage. Every replacement checks that its target text exists and the build stops with an error if not, so a change to the shared source cannot quietly produce a half-built app. A jsdom smoke test then loads each built page and clicks through it: tabs, search, the command palette, adding to the queue, downloading both script formats, and saving a profile.

The result has no build step to run and no backend, so it is light and works from GitHub Pages. Icons are from Lucide and the fonts are Bricolage Grotesque, Instrument Sans and JetBrains Mono. The code lives in the source repository.

5 How it got here

The first version, in June 2025, was a single HTML page generated with Gemini 2.5 Pro and then updated with Claude Sonnet 4. It grouped options into a few sections and could add commands to a batch and download them as one .bat file. In December 2025 I gave it a Fluent-style redesign with Gemini Pro, and the same month built a Wget counterpart in the same style.

In November 2026 I rebuilt both as Conduit, with Claude as a pair programmer. That redesign added the tabs, the risk labels, search, the command palette, paste-to-fill, profiles, PowerShell export and coverage of every option in robocopy /?. The hand-drawn icons were replaced with unmodified Lucide icons, inlined so the app is still one file.

  • IT professionals setting up backup routines
  • Anyone copying large directory structures with specific parameters
  • Learning Robocopy syntax by seeing what each option does
